## 实施安排

| 顺序 | 工作 | 验证重点 |
| --- | --- | --- |
| 1 | 按已确认范围整理模式状态和接口 | 遵循已确认 JSON 字段与事务规则，引用有效，未确认行为不进入实现 |
| 2 | 验证单篇文本导入与训练扩展兼容 | 一次粘贴一篇，保留用户行边界，不引入自动分篇或多篇拆合 |
| 3 | 扩展共享会话、识别确认和完整正文比较 | 模式差异由数据表达，漏句后续仍正确对齐，不复制训练业务 |
| 4 | 实现多模式存储、统一用户数据导出和原子恢复 | 草稿／课文状态保留，单句／全文范围校验分清，UUID 覆盖合并、本机独有记录保留、失败回滚和旧写入失效 |
| 5 | 接入全文页及统一记录／结果 | 提交前隐藏答案，历史只读、类型标签明确、删除及重练可用 |
| 6 | 验证核心输入适配器与不同规则测试模块 | OCR／ASR 固定输入、失败、取消、旧任务返回；三种训练均可复用 |
| 7 | 完成必要回归、容量与性能验证及用户交付 | 逐项记录 C／A 覆盖、实际结果与未验证边界 |

粘贴文本保持一次一篇，按用户换行确定句子；课号、标题或空行不触发自动分篇。多篇提议与草稿拆合仅在后续文件提取或识别阶段处理，本阶段不实现相关界面。

全文键盘直接比较整篇输入；背诵的原始转写、确认文本、修改标记及结果关系通过测试适配器验证，不建立模拟背诵用户页面。固定手写识别文本通过测试适配器验证相同确认契约，不在页面提供不可用的照片入口。

共享结果组件继续使用原文范围标色；完整正文的参考范围属于课文，输入范围属于整篇作答，不能用输入换行或相同句序号替代完整序列对齐。全文只支持重新默写全文，逐句结果继续保留错句重练；两者均创建新会话。

### 自动验证计划

- 核心测试：三种模式的提交／确认、跳过与重练契约；整句遗漏、开头／结尾多余、重复句、跨句对齐、Unicode 映射及单位计数；至少一种不同单位或提示结构的测试模块复用全部模式。
- 导入测试：粘贴含多个课号或标题的文本仍只形成一篇草稿，保留行边界；空句与超限、未选语言阻止原始材料分析；JSON 保留各对象语言与状态，不重新校对。
- 存储与序列化测试：全部已保存用户内容的 JSON 往返，包括多种语言、课文草稿、全文输入草稿、三种模式历史与来源依赖；同 UUID 完整覆盖、旧文件覆盖较新进度、草稿／课文跨状态覆盖、本机独有记录保留、重复导入不增加记录、事务回滚、旧写入失效、未知版本、损坏范围和缺失模块；历史结果不能重算。
- 适配器测试：固定 OCR／ASR 文本、确认修正与未修改标记、失败重试、取消后旧结果返回、内容语言全程传递；无模型、无网络、无 DOM 的核心测试可运行。
- 浏览器测试：全文输入到结果、错句重练、多模式记录查看／删除、导入导出恢复；回归逐句、导入草稿、复制正文和行号选句，验证窄屏及输入法合成。
- 工程验证：按工程指南执行类型检查、lint、单元／集成测试、关键浏览器流程和生产构建。性能使用既定样本方法测量分析与对齐，验证大量记录的导入导出及实际处理失败的回滚，不设置用户数据总量或 JSON 容量拒绝阈值，不将目标写成已通过。

核心验收逐项映射 A01–A32：C02／A01／A02 的文件多篇提议与拆合、A03 留待文档提取与识别；涉及录音、OCR／ASR 的 A15／A16／A24 在本阶段仅验证固定输入适配器及共享状态，真实设备、权限和识别质量仍留待对应 Web 阶段。本阶段适用的功能或契约缺口必须关闭，不能用逐句已经通过替代全文验证及背诵核心契约测试。
