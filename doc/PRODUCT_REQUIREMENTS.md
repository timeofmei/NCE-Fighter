# NCE Fighter 产品需求

版本：0.3　日期：2026 年 10 月 11 日

本文用于确定核心引擎的开发范围、业务规则、页面交互和验收标准。产品只开发 Web，覆盖桌面端和移动端现代浏览器，不支持老旧浏览器。首个开发里程碑仍交付平台无关的统一业务引擎和可分别开发的语言文本模块，并用最小 Web 演示验证闭环；后续接入浏览器本地 PDF、OCR 和 ASR。用户在上传或输入课文前明确选择内容语言，应用不自动识别语言。

本版整合用户提供的浏览器本地技术方案。明确的平台新决策更新为 Web；附件其他内容与原需求冲突时保留原需求，具体处理见本文第 12 节。模型和浏览器能力需锁定版本并实测，技术候选不等于已经实现的功能。

本文保留原 PRD 的章节编号。返回[文档索引](NCE_Fighter_MVP_PRD.md)；引擎、页面、交付与 Web 接入规格见索引中的专题文档。

## 1 产品目标与已确定决策

NCE Fighter 帮助学习者把自己提供的不同语言课文整理成可信的标准答案，再通过逐句默写、全文默写和整篇背诵反复练习。产品名保持 NCE Fighter，英语是支持语言之一。主要检查内容是否记住，不评价发音。

| 决策 | 产品规则 |
| --- | --- |
| 逐句默写提示 | 支持无提示和提示两种模式 |
| 背诵范围 | 只支持整篇背诵，结束后统一检查 |
| 大小写与标点 | 全部训练统一忽略，不提供严格开关 |
| 第一版重点 | 平台无关的核心引擎，客户端和识别模型通过接口接入 |
| 内容语言 | 用户在上传文件、粘贴文本或导入 JSON 前选择，不自动识别 |
| 语言差异 | 各语言文本模块由开发者分别实现；语言无关的业务逻辑、接口和页面统一 |
| 客户端平台 | 只开发响应式 Web，同时考虑桌面端和移动端浏览器，不支持老旧浏览器 |
| Web 识别路线 | 浏览器本地处理；原生本地能力优先，必要时使用库或本地模型 |
| Web 发布方式 | 静态站点与模型资源托管，不建设业务或识别后端服务器 |

以下为本版提出的默认设计，未视为用户已经确认的新增决策：英语提示采用逐词首字母，其他语言由其模块定义提示；无提示为默认模式；输入一句后点击提交才出结果；课文正文参与比对，标题、课号和页眉不参与；一批导入材料使用一个用户选定的语言。上述默认值可调整，不应改变统一业务层、语言模块和平台适配层的边界。

首版成功的判断：已校对课文可以进入三种训练；相同语言、规则版本和文本输入得到可复现的差异；漏写整句不会使后续正确内容连续误判；新增语言不需要复制训练流程；引擎无需浏览器、手机系统、网络或模型即可通过验收。多语言架构不等于全部语言已经可用，正式支持列表以已实现并验收通过的语言模块为准。

## 2 交付范围与优先级

### 2.1 核心引擎 MVP

| 编号 | 必须交付 | 最小验收输出 |
| --- | --- | --- |
| C01 | 先选语言，再导入纯文本或结构化课文 | 带 languageId 的可编辑课文草稿列表 |
| C02 | 多篇课文边界建议 | 标题、正文、原顺序与待确认项 |
| C03 | 句子切分与人工调整 | 稳定句子 ID、顺序、原文范围 |
| C04 | 标准答案确认与版本 | 只有已确认版本可以训练 |
| C05 | 按语言归一化、比较单位对齐、差异统计 | 正确、遗漏、多余、替换及原文位置 |
| C06 | 逐句默写状态与两种提示 | 逐句提交、重试、跳过、完成汇总 |
| C07 | 全文默写与整篇背诵状态 | 获取完整文本后统一比对 |
| C08 | 训练记录与序列化 | 可保存、恢复及导出课文和训练数据 |
| C09 | 输入能力与存储接口 | 无真实模型也能用测试适配器跑通流程 |
| C10 | 最小验证入口与验收用例 | 用文本模拟 OCR 和 ASR，验证闭环 |
| C11 | 语言模块注册、选择与能力查询 | 未选语言或模块未安装时明确阻止导入 |
| C12 | 统一语言模块契约与共享业务验证 | 各语言返回相同结果结构，复用全部训练状态 |

### 2.2 Web 接入范围

截图、照片、多个 PDF、麦克风录音和手写照片都是正式产品的输入目标。核心引擎首版规定输入契约和页面状态；真实文件解码、OCR、录音、ASR、权限申请、文件选择及持久化由浏览器适配层负责。OCR 和 ASR 显式接收用户所选 languageId；应用不调用语言自动识别流程，也不根据模型返回内容自动改选语言。文本模块支持某语言，不代表 OCR 或 ASR 同时支持它，能力按语言和输入方式分别查询。

Web 接入阶段使用本地文件选择、移动端拍照入口、PDF.js、浏览器录音及本地识别模型。这里的“上传”指把用户文件读入当前浏览器，不发送文件、音频、正文或识别结果到远程识别服务。允许在线下载站点程序、运行时和模型资源；页面刷新恢复、文件缓存与完全离线运行分别验收。没有云端识别兜底，也不要求用户配置模型 API Key。

文字版 PDF 优先直接提取文本；扫描页走 OCR；混合 PDF 按页判断，可组合两种方式。多个文件保持用户选择顺序，同一篇跨页课文可以合并，一页多篇可以拆分。失败项目允许单独重试，已经成功的草稿保留。

首版可以用粘贴文本和结构化 JSON 演示导入，用转写文本演示整篇背诵结果，用识别文本演示手写全文检查。这验证核心逻辑，不代表已经实现图片、PDF、录音或手写识别。

核心引擎 MVP 不包含账户体系、云同步、内置整套教材、发音评分、自动学习计划、模型训练或模型下载管理。Web 接入阶段增加必要的模型按需下载、缓存与清理，不改变核心引擎 MVP 范围。错句集合与重练入口复用现有结果，不要求建设独立的学习推荐系统。

## 3 核心用户流程

选择内容语言 → 导入材料 → 使用所选语言模块获取和整理候选文本 → 调整课文边界 → 校对正文及句子 → 确认标准答案 → 选择训练 → 提交或确认输入 → 查看差异 → 重练或返回课文。

语言选择对上传文件、粘贴文本和导入 JSON 都是必填前置步骤，没有“自动检测”选项。同一批材料沿用一个选择；不同语言分别建立导入批次。结构化 JSON 自带语言时，应在导入前与用户选择核对，冲突时阻止静默导入并要求明确处理。推荐使用明确语言标识，如 en、zh-Hans、ja；地区和文字变体是否另设模块由开发者决定，映射必须显式注册，不自动退回英语。

语言在整个流程中保存并传递。草稿阶段改选语言需要重新执行语言相关的课文划分、分句、归一化与提示生成，必要时重新识别，清楚提示哪些人工调整需要重新确认。已确认课文改语言产生新版本；历史会话使用原语言及原模块版本。课文中少量外语片段由所选主语言模块规则处理，首版不自动分配混合语言模块。

识别和校对之间必须有明确确认步骤。OCR 或模型返回的内容不能直接成为标准答案；没有可信边界时标记“待确认”，不猜测或补写原文。

训练会话绑定开始时的课文版本、languageId、语言模块及规则版本。训练期间修改课文或升级模块不会覆盖本次标准答案或比较规则；新的训练使用明确版本，旧记录仍能还原当时的标准答案和结果。

## 4 详细功能需求

### 4.1 导入与课文校对

**I01 输入结果。** 适配器提供 languageId、文本块、来源 ID、页号或图片区域等定位信息；没有定位信息的纯文本也能处理。文字识别必须保留可读原文，不能只提供已经去掉标点的文本。

**I02 课文划分。** 优先依据课号、标题、空行和来源顺序提出分篇建议；不把页面等同于课文。统一业务层处理来源顺序和人工拆合；标题、课号等语言相关模式由语言模块提供。不同文件默认分开，不自动跨文件合并；用户可以主动合并同语言课文。没有明确标题的文本先形成一个待确认草稿。英语模块建议识别 Lesson 加编号；其他语言分别定义模式，不强制沿用英语规则。

**I03 校对操作。** 可改标题与正文，可在指定位置拆分课文、合并相邻同语言课文、删除误识别内容、拆分和合并句子。调整后调用所选语言模块重新计算比较单位数量与提示。训练正文为唯一文本源；句子通过正文范围引用，避免正文与句子列表各存一份后失去同步。

**I04 分句规则。** 所选语言模块在保留标点的原文上分句，再归一化用于比对。英语模块覆盖缩写、人名首字母、小数等；其他语言分别覆盖其句尾符号、引号、换行和语言特有边界。Mr. Smith 是英语用例，不作为所有语言的共同规则。对话保留原顺序，说话者标签是否属于正文由校对时确定。统一层验证句子范围并提供人工修正，分句建议可以有歧义。

**I05 保存门槛。** 标题可手工补充，正文至少包含一个所选语言模块定义的比较单位；确认前显示语言、正文和句子列表。发现语言未选择、模块不可用、空正文、重叠或越界范围时阻止确认，并定位问题。识别空结果不自动补全。仅含大小写或标点调整的版本也保留原文变化，但不改变比对规则。

### 4.2 逐句默写

**S01 无提示模式。** 仅显示课文标题、内容语言、当前句序号和进度，不显示当前原句、比较单位数量、释义或任何语言提示。进入下一句时收起上一句答案，避免泄露上下文。默认模式为无提示。

**S02 提示模式。** 统一业务层只管理提示显示、切换与使用记录，提示内容由各语言模块生成。英语模块建议逐词首字母，例如 I had a very good seat. 显示 i h a v g s；其他语言可设计局部字符、遮盖或其他确定性提示，具体方案由开发者定义，不能机械套用首字母。模块返回 hintLabel 与结构化提示片段，页面使用“提示／无提示”及当前语言提示名称。不默认生成译文、拼音或罗马字；这些若采用需在该语言规则中明确。正式支持模块应实现提示能力，模块尚未完成时明确标注，不暗中显示完整答案代替提示。

**S03 切换与记录。** 提交前可以切换提示；只要当前作答展示过提示，该作答的 hintUsed 始终为 true，关闭提示不会清除记录。无提示通过与提示通过分别汇总。重试是新的作答记录，不能覆盖第一次结果。

**S04 提交与反馈。** 用户输入完整一句，点击“提交本句”，立即显示确定性差异；不在打字时不断展示答案。多行输入可用按钮提交；桌面可提供 Ctrl 或 Cmd 加 Enter，普通 Enter 保留换行。输入为空或仅标点时禁用提交。

**S05 操作。** 提交后允许“重写本句”和“下一句”。重写收起标准答案、清空本次输入，但标记该句已经看过答案。跳过后才能显示原句，跳过不计为通过；末尾提供错误句与跳过句的重练入口。

**S06 汇总。** 显示首次独立正确句数、首次提示正确句数、错误句数、跳过句数与重试次数。已经查看答案后的正确重写显示“复练正确”，不能记入本次首次独立通过。正常流程里这四个首次分类覆盖全部句子。

### 4.3 全文默写

**F01 键盘输入。** 原文在作答期间隐藏；用户一次性输入全文，点击“提交全文”后统一反馈。允许输入自然换行，但不依赖用户句号和句子编号进行对齐。正文未提交时不显示逐句判断或正确率。

**F02 手写输入。** 拍照或上传多张图片 → 调整图片顺序 → 必要的裁切与分行 → 本地手写 OCR → 展示识别文本与来源 → 用户校对确认 → 全文比对。OCR 原始结果和用户确认版本分别保存；没有接入该语言且通过验收的手写能力时显示“当前版本暂不可用”。印刷体 OCR 可用不代表手写识别已经通过，手写仍是独立能力和产品目标。

**F03 持久化。** 存储接口可保存输入草稿和当前阶段；客户端应提示保存失败。重复点击提交通过请求 ID 去重，不产生两条相同记录。提交后修改输入作为新作答，不改写历史结果。

### 4.4 整篇背诵

**R01 背诵。** 查看课文准备后开始录音；开始时隐藏正文。一次连续完成整篇，页面只提供“结束背诵”和“取消”，不提供按句暂停或下一句。静音不能自动当作整篇结束。

**R02 转写。** 结束后生成完整 ASR 文本，先让用户查看并纠正识别错误，再点击“确认文本并检查”。录音中不展示标准答案、差异或基于原文的实时进度；显示录音状态与时长即可。

**R03 输出口径。** 结果注明“基于确认后的识别文本比对”，不称为发音评分。用户修正识别文本只为修复识别错误；原始转写与修正版分别保留，结果标记是否编辑过。

**R04 异常。** 权限拒绝可重新授权或返回；转写失败保留已完成录音供重试；来电或录音中断显示“录音中断”，用户可结束并检查已有片段，或放弃并重新录整篇，不自动判定背诵完成。只说了部分课文后主动提交，未说部分显示遗漏。

**R05 整篇与处理批次。** 保留整篇一次录制、结束后统一确认和比对。附件的 180 秒用于首轮 ASR 性能基线及内部处理批次；不能要求用户每三分钟结束、按句提交，不能到时截断或自动判完成。较长录音可在结束后内部拆成不超过 180 秒的任务，再以约 30 秒模型窗口处理和去重拼接。应用总录音上限由设备验收另行确定并在开始前说明；未验证长录音时明确限制，不承诺无限时长。

## 10 开发前需冻结的建议默认值

1. 统一默认无提示，展示提示后本次作答永久标记；具体提示按语言定义，英语建议首字母。
2. 各语言模块分别冻结分句、归一化、比较单位、提示和对齐规则；忽略大小写和标点是共同要求，文字等价关系不能套用英语规则。
3. 标题与课号不参与正文比对；对话说话者标签在校对时处理。
4. 首次表现与复练表现分别保存；识别原始文本与用户修正版分别保存。
5. 核心引擎首版只承诺核心闭环；真实本地识别和正式响应式 Web 列入独立接入里程碑。
6. 一批材料选一种主语言，混合内容由该模块处理；不同语言分别导入，内容语言与界面语言独立。
7. 首批正式支持的语言与模块版本由开发者明确公布；可扩展架构不承诺所有语言已经实现。
8. Web 浏览器最低版本、模型文件与精度、扫描分辨率、并发、录音上限及设备性能门槛在对应接入阶段实测后冻结。

这些默认值使工程可以先开始，后续变更通过语言模块版本、课文版本和接口扩展处理，避免历史记录含义随实现改变。新增语言的开发范围集中在其文本模块和相应识别能力，统一业务层保持复用。

## 12 与原需求的冲突及采用规则

| 项目 | 附件建议或原文差异 | 本文采用规则 |
| --- | --- | --- |
| 平台选择 | 原文平台未定，新指令明确只做 Web | 采用用户最新明确决定；仅开发桌面及移动浏览器 Web，核心继续独立 |
| 开发顺序 | 附件从 PDF、OCR、ASR 开始 | 保留核心引擎优先的 M1 至 M4，附件顺序用于后续 M5 至 M7 |
| 首版模型下载管理 | 原核心 MVP 明确不包含，附件包含缓存与管理 | 核心范围不扩张；必要资源管理属于 Web 接入阶段 P08 |
| 英语优先及最后扩展语言 | 附件建议后期增加可选语言 | 保留从一开始注册多语言模块和预选语言；英语仅作为首轮识别性能基线 |
| 三分钟音频限制 | 附件每段最长 180 秒，原需求整篇背诵一次完成 | 保留整篇流程；180 秒用于内部处理批次和测试，不强迫用户分段，不默认截断 |
| 原生语音接口 | 部分原生方案适于录音中识别，原需求结束后统一检查 | 默认结束后本地批量转写；可选接口不能暴露逐句结果或改变训练状态 |
